# Full Stack DS for Unity UI Toolkit

A local UPM package with contract-generated Switch, Accordion, Popover, Tabs, Text, Divider, Icon, Button, Checkbox, ToggleSwitch, Blockquote, Stat, ProfileFlag, Badge, List, Alert, AlertNotice, Label, Breadcrumbs, Tooltip, Status, Card, NavList, Skeleton, Table, CodeBlock, Details, Progress, Chip, CodeSnippet, Dialog, Sheet, Input, TextField, Toast, Field, Walkthrough, Links, Image, Avatar, NavTree, Postcard, Pagination, OTP, RadioGroup and Select controls. Unity 6 is the API baseline. Generated controls carry `[UxmlElement]` and are usable from C#, UXML and UI Builder; the same runtime assembly serves Editor windows and `UIDocument` panels.

## Import

In Unity's Package Manager, choose **Install package from disk** and select this directory's `package.json`. Keep the package directory at a stable path. This is a local package, not a published Unity registry dependency.

Open **Window → Full Stack DS → Interactive Controls** for the C# showcase. Import **Interactive controls** from the package's Samples section to get `Controls.uxml` and `RuntimeExample.cs`. Open the UXML in UI Builder. For runtime use, assign it to a `UIDocument` with a `PanelSettings` asset and add `RuntimeExample` to that GameObject.

```xml
<ui:UXML xmlns:ui="UnityEngine.UIElements" xmlns:ds="FullStackDS">
    <ds:Switch checked="true"><ui:Label text="Enable sound" /></ds:Switch>
    <ds:Accordion collapsible="true">
        <ds:AccordionItem>
            <ds:AccordionHeader><ds:AccordionTrigger value="graphics" text="Graphics" /></ds:AccordionHeader>
            <ds:AccordionContent value="graphics"><ui:Label text="Rendering preferences" /></ds:AccordionContent>
        </ds:AccordionItem>
    </ds:Accordion>
    <ds:Tabs>
        <ds:TabsList>
            <ds:TabsTab value="first" text="First" />
            <ds:TabsTab value="second" text="Second" />
        </ds:TabsList>
        <ds:TabsPanel value="first"><ui:Label text="First panel" /></ds:TabsPanel>
        <ds:TabsPanel value="second"><ui:Label text="Second panel" /></ds:TabsPanel>
    </ds:Tabs>
    <ds:Popover>
        <ds:PopoverTrigger text="Help" />
        <ds:PopoverContent><ui:Label text="Helpful content" /></ds:PopoverContent>
    </ds:Popover>
    <ds:Button variant="primary">Resume</ds:Button>
</ui:UXML>
```

## State and composition

Each generated root builds the contract's anatomy as a `VisualElement` tree: every part carries `name="<part>"` and the class `<prefix>__<part>`, and the contract's children hole is the root's `contentContainer`. Compound parts are separate generated elements composed by the consumer, as on the web: `AccordionItem`, `AccordionHeader`, `AccordionTrigger`, `AccordionContent`; `TabsList`, `TabsTab`, `TabsPanel`; `PopoverTrigger`, `PopoverContent`. Accordion and Tabs trigger and content parts carry a `Value` pairing key; every trigger part carries `Disabled`. Variant props set a root modifier class `<prefix>--<value>` (`tabs--pills`, `accordion--multiple`), as the web class recipe does.

The constructor attaches one behavior by contract fact and exposes it: `Switch.Control` (`BooleanControl`), `Accordion.Group` / `Tabs.Group` (`ItemGroup`), `Popover.Surface` (`AnchoredSurface`), `Details.Disclosure` (`DisclosureControl`), `Progress.ValueFill` (`ProgressControl`); `Chip` composes its trigger references as native action chrome (no runtime class); `Dialog.Surface` and `Sheet.Surface` (`ModalSurface`) are the blocking modal family, and `Input.Control` and `TextField.Control` (`TextControl`) are the string text-channel form controls, `Toast.Surface` (`ToastSurface`) is the ephemeral viewport notification surface, `Field` is the slot-only form row scaffold, `Walkthrough` is the inline coachmark tour card, `Links` is the navigation-request anchor scaffold, `Image` is the native texture media element, `Avatar` composes it with a guarded initials fallback, `NavTree` is the nested navigation scaffold, `Postcard` is the static article with projected object-path text, `Pagination` is the runtime-built numeric page strip, `OTP` is the runtime-built single-character field group, `RadioGroup` renders native radio choices from a declared option list, and `Select` is the two-channel listbox runtime. Switch uses `Checked`, `value`, `SetValueWithoutNotify` and Unity's `RegisterValueChangedCallback`; its children are the label, and a click on the label outside the control toggles it once. Popover uses `Open` and the same boolean-channel APIs. Both expose the native `Trigger` button; Popover also exposes `Content`.

Accordion and Tabs expose `Value`, `Values`, `ValueChanged`, and `Group.SetValuesWithoutNotify`. The group discovers trigger and content sub-elements by part class under the root and pairs them by `Value`; trigger values must be non-empty and unique. Discovery runs on panel attachment, before pointer or submit input reaches a trigger, on root layout changes and on every public mutation; call `Group.Synchronize()` after inserting parts imperatively into an attached root if presentation must update before the next input. A part moved to another root leaves its previous group. Nested components keep their own parts.

Accordion defaults to single selection with `Collapsible = false`; use `Type = "multiple"` and `Values` for multiple sections. Tabs supports horizontal/vertical orientation, automatic/manual activation, looping, disabled items, Home/End, arrow navigation and `UnmountInactive`. Native UI Toolkit buttons own pointer and submit activation. Accordion's vertical arrows move focus without selecting.

`Button` is an action control rather than a channel: the generated class derives the native `UnityEngine.UIElements.Button`, so pointer activation and Space/Enter submit activation are the platform's. Assign `OnClick` to receive activation; `Disabled` gates it through `SetEnabled`. Consumer content composes into the control's own content container; the contract's loading-text wrapper is flattened and the guarded loading chrome is omitted (pending P4). `Size` / `Variant` set the `button--<size>` / `button--<variant>` class carriers. The contract's pending state is not realised: `Loading`, the ARIA state props and the HTML form `type` are refused by the support boundary, so the control exposes no loading affordance and consumers own any pending presentation.

`Checkbox` and `ToggleSwitch` are the second and third boolean forms of the same `BooleanControl` behavior. `Checkbox` is a label-host control: the generated root is the label host, the native control is a `Button` exposed as `Trigger`, and a click on the label outside the control toggles `Checked` once. `ToggleSwitch` is a root-control form: its form-control part is the root, so the generated class derives the native `UnityEngine.UIElements.Button`, exposes `Trigger => this`, and activation (pointer or Space/Enter) commits the checked channel. Both expose `Checked`, `value`, `SetValueWithoutNotify`, `RequestValue`, `Controlled`/`ValueRequested` and `Disabled`; the checked channel is observable as a `ChangeEvent<bool>` on the root. Each contract's `size` axis is withheld because its styles sidecar carries no size-predicated carrier, and the indeterminate/mixed state, ARIA relationship props and form fields are refused by the support boundary.

`Blockquote`, `Stat` and `ProfileFlag` are passive containers: each generated root is a `VisualElement` whose `contentContainer` is the consumer's composition point, and only carrier-backed style axes are exposed — `Blockquote.Variant`/`Size` and `Stat.Size`/`Trend`, each switching the root modifier class (`blockquote--bordered`, `stat--up`). Blockquote's citation `cite` URL is refused (no UI Toolkit consumer) and ProfileFlag's structured `profile` prop is pending P4 typed-declaration lowering, so neither generated control exposes those props; ProfileFlag is an identity shell plus the consumer's content.

`Badge` is a carrier-backed container with a composed content part: `Badge.Variant` (`default`/`status`/`counter`/`tag`), `Badge.Intent` (`info`/`success`/`warning`/`danger`) and `Badge.Size` (`sm`/`md`/`lg`) switch the root modifier classes, and consumers compose a `BadgeContent` sub-element for the label or count (as with Accordion's compound parts). The contract's guarded icon decoration is a dynamic node-content prop, so the lowering omits it by fact: `icon` is pending P4 node-content projection and `showStatusIcon` is refused; the generated control exposes neither property.

`List` is a semantic container whose colliding variant axes use prefixed modifier carriers: `List.Variant` (`default`/`unstyled`/`inline`/`divided`/`spaced`) and `List.Size` (`sm`/`md`/`lg`) switch `list--variant-<value>`/`list--size-<value>` through the runtime `Variants.GetAxis`/`SetAxis` helpers, and items compose directly on the control. The contract's polymorphic `as` prop is refused, `marker` is refused because USS has no `list-style-type`, and `spacing` is pending P4 because its rules select sibling children with combinators the native selector grammar refuses; the generated control exposes only `Variant` and `Size`.

`Alert` and `AlertNotice` are static alert containers: `Alert.Intent` (`info`/`success`/`warning`/`danger`) and `Alert.Level` (`inline`/`section`/`page`), or `AlertNotice.Status` (`info`/`success`/`warning`/`error`) and `AlertNotice.Level`, switch the root modifier classes, and consumers compose content plus the `AlertBody`/`AlertTitle` (or `AlertNoticeBody`/`AlertNoticeTitle`) parts. Both contracts' guarded chrome — the node-content icon and the dismiss control (a composed Button on Alert, a native button on AlertNotice) — is omitted by fact: the generated controls expose no `Icon`, `Dismissible`, `OnDismiss` or `DismissLabel`, and the dismissal style selectors stay pending P4.

`Label` is a text wrapper deriving `TextElement`: set its `text` property or compose children, and its DOM form-association props (`htmlFor`, `form`) stay pending P4. `Breadcrumbs` is a semantic wrapper whose consumer composes `BreadcrumbsList` and `BreadcrumbsItem` parts; its a11y label binding is refused (UI Toolkit exposes no assistive-technology tree) and the `separator` prop is refused because separators are consumer-composed. The generated `FullStackDS.Label` shadows the native `UnityEngine.UIElements.Label` for code that imports `FullStackDS`, so native labels must be qualified there.

`Tooltip` is a hover/focus-open anchored surface: consumers compose a `TooltipTrigger` (a native action control) and a `TooltipContent` (non-interactive, never focus-trapped). It opens on pointer enter and trigger focus, and closes on pointer leave, blur and Escape; `CloseOnEscape`/`CloseOnBlur` name the contract's enabled-by flags, `Placement` drives the anchored placement, and `Disabled` disables the trigger and suppresses hover opening. It exposes no outside-click dismissal and no retained-state guarantee for the ephemeral content.

`Status` is an inline status pair: the root carries the `StatusValue` axis (`info`/`success`/`warning`/`danger`/`error`) switching the `status--<value>` modifier, and consumers compose text through `status.contentContainer` (the `StatusLabel` part). The contract's decoration-role Icon instance is omitted by fact (component composition is pending P4), so the generated control exposes no icon API. The member is named `StatusValue` because C# forbids a member sharing its enclosing type's name.

`Card` is a parts-only composed container: the root carries the `Density` axis (`default`/`inset`) and consumers compose the subcomponent parts `CardHeader`, `CardMedia`, `CardContent`, `CardFooter`, `CardActions`, `CardBadge`, `CardDescription`, `CardLink` and `CardNote`. The `interactive` hover affordance is pending P4 and the generated control exposes no `Interactive` property; `CardLink` is a container region a consumer fills (for example with a composed Button) rather than a live action. Godot admits Card too, so this closes that contract's cross-engine parity gap.

`NavList` is a semantic navigation container: consumers compose a `NavListList` region and `NavListItem` entries (marking the active entry on their own anchor content). The legacy styled `orientation` prop is pending P4 because its sidecar carries no USS layout carrier, and the a11y label binding has no native tree, so the generated control exposes neither `Orientation` nor `AriaLabel`.

`Skeleton` is a carrier-backed loading placeholder: `Variant` (`block`/`text`/`avatar`/`media`/`dataviz`/`actions`), `Animate` (`shimmer`/`wipe`/`pulse`/`none`) and `Density` (`compact`/`regular`/`spacious`) switch modifier classes. The contract's iterated stack/row/shape anatomy is omitted by fact (iteration is pending P4), so a multi-line skeleton is not rendered; the control is a single placeholder block. No shimmer animation is claimed — transitions, `::after`, `:has` and the slide animation facts are ledgered or pending — and `lines`, `radius`, `aspectRatio`, `decorative` and `ariaLabel` are not exposed.

`Table` is a semantic table container: the root wrapper exposes the `Container` region (a `table`-classed element routed as `contentContainer`) and consumers compose `TableCaption`, `TableHead`, `TableBody`, `TableFooter`, `TableRow`, `TableHeaderCell` and `TableCell` regions with their own native cell content; headers' sorting and arrow-key row navigation are consumer responsibilities. No `Responsive` or `AriaLabel` API is emitted: the responsive overflow wrapper and aria labeling are pending/refused, and the contract's keyboard/sort declarations are refused because no channel or projected action root realises them.

`CodeBlock` is a styled code shell: consumers compose line labels through the `Code` region, which backs `contentContainer`. The contract's syntax-highlight content transform, token stream, line numbers, gutter and language metadata are omitted or withheld by fact (content-transform and iteration families are P4); no `Language`/`Highlight`/`Tokens`/`ShowLineNumbers` API is emitted, and `white-space: pre`, `tab-size` and `font-size: inherit` declarations are refused rather than approximated.

`Details` is the disclosure form: a native `Button` summary (`Trigger`) toggles a boolean `Open` channel and the content region's visibility, `Summary` paints the summary `Label`, and the root exposes the same `Open`/`value`/`SetValueWithoutNotify`/`RequestValue`/`Controlled`/`ValueRequested` channel API as the other boolean controls plus `Disabled`. The trigger's summary text is a generated string attribute projected from the contract's content binding; the decoration icon is a composed glyph instance, and the `variant`/`icon` axes switch their modifier classes. The `<details>[open]` chevron-rotation selector and the a11y label binding are refused/pending, so no expanded-state styling or ARIA tree is claimed.

`Progress` is the value-fill form: a numeric `Value` (clamped into the contract's declared 0-100 range) is projected to the fill's native percentage width, `ShowValue` toggles the presence of the consumer-filled value region (which backs `contentContainer`), and `Intent` switches its carrier class. The contract's `variant` (linear/circular), `size`, `label` and `formatValue` are withheld/pending and the authored calc-var fill width is refused, so no formatted value text, circular layout or ARIA value tree is claimed.

`Chip` is composed action chrome: its action and guarded dismiss trigger references render as native `UnityEngine.UIElements.Button`s carrying `chip__action`/`chip__dismiss`, the consumer label is composed into the action button through `contentContainer` (the text region), and the generated `OnClick`/`OnDismiss` Action properties are invoked from the native buttons' clicks. `Dismissible` hides or shows the dismiss chrome and `Disabled` disables the root and both buttons; `Variant`/`Size` switch their modifier classes. The referenced Button component's own visuals are not composed, and its form `type` attributes, ARIA state/label and the icon node content are withheld/refused rather than approximated.

`CodeSnippet` is a passive text-content host: the generated class derives `TextElement` and the contract's `text` prop becomes a generated string attribute painting the element's text; the `as` axis switches its carried modifier classes (`code-snippet--kbd`, `code-snippet--samp`). The underlying HTML element switch (code/kbd/samp) is not realised and no tag API is emitted; the authored `spellcheck` attribute and the kbd elevation are withheld by the boundary.

`Dialog` is the blocking modal form: `Surface` (`ModalSurface`) portals the host to the panel root, fills it, centers the modal panel over a backdrop, traps Tab/Shift+Tab inside the open panel, and closes through the declared policy — `CloseOnEscape`, `CloseOnBackdropClick` and the close button's native activation. `Open`/`value`/`SetValueWithoutNotify`/`RequestValue`/`Controlled`/`ValueRequested` follow the standard boolean channel, `Dismissible` hides the close button, `Size` switches its modifier class, `TitleSlot`/`FooterSlot` are named insertion points and `Body` is the content region. The ARIA tree, DOM focus-target ids, non-modal mode, page scroll lock and viewport-unit styles are refused/pending rather than approximated; presence is display-based (hidden, not unmounted).

`Sheet` reuses the same modal surface for a viewport-edge blocking panel: `Surface` portals and traps focus like Dialog, and the `Side` axis (`top`/`right`/`bottom`/`left`) switches its modifier class while also driving the runtime's edge alignment (`Placement`). `CloseOnEscape`/backdrop-click dismissal and the close trigger's activation close the panel; `TitleSlot`, `DescriptionSlot` and `FooterSlot` are named insertion points and `Body` is the content region. Sheet exposes no dismissal-gate or ARIA properties, its panel styles keep the viewport-unit/data-side declarations refused/ledgered, and presence is display-based.

`Input` is the first form control: the generated class derives the native `UnityEngine.UIElements.TextField`, the string value channel is exposed as `Value` with `Controlled`/`ValueRequested`, a silent `SetValueWithoutNotify` and `RequestValue`, and `Placeholder` drives the native text edition. User edits run through the native change event; in controlled mode the runtime reverts the native value until the owner commits. `Disabled` disables the field. HTML input `type`, form `name`/`required`, validity/ARIA state and form serialization are refused rather than approximated, so no form-field API is claimed.

`TextField` is the labeled wrapper form: the root is a `VisualElement` whose native field child (`Field`, a `UnityEngine.UIElements.TextField`) carries the string channel through the same `TextControl` adapter, while `LabelSlot`, `DescriptionSlot` and `ErrorSlot` are named insertion points. It exposes the same `Value`/`Controlled`/`ValueRequested`/silent setter/request API and `Disabled`; HTML form participation/serialization, input type, required/name, ARIA relationship bindings and validity state are refused, and the invalid-state selectors are ledgered pending. The generated class shares the native `TextField` name, so native references in the runtime and tests are fully qualified.

`Toast` is the non-blocking ephemeral notification: the generated class is the viewport host (`ToastSurface` portals it to the panel root and anchors it to the bottom-right edge), the open channel drives the item's presence, `Duration` (milliseconds) runs the auto-dismiss timer, `Title` paints the title label, `Variant` switches the info/success/warning/error modifiers and the close control plus Escape request a close. `ActionSlot` and `Description` are named insertion points. Politeness/ARIA live-region state and the animated progress bar are not realised.

`Field` is the slot-only form row: a `VisualElement` scaffold with `Header`/`LabelSlot`, `Control`/`ControlSlot`, `Meta`/`HelpSlot`/`ErrorSlot` and `ValidatingIndicatorSlot` insertion points, plus a `Status` modifier carrier (`idle`, `validating`, `valid`, `invalid`). It owns no context propagation or validation runtime: the value channel, `name`/`id`/`required`/`disabled`/`readOnly`/`validate`/`validating` props and the validating-indicator guard are withheld/ledgered pending, and the consumer wires the control it composes into the control slot.

`Walkthrough` is the inline coachmark card: `TitleSlot`/`DescriptionSlot` named hosts, native `Skip`/`Prev`/`Next` controls wired to generated `OnSkip`/`OnPrevious`/`OnNext` actions, an `Index` step attribute the consumer manages, `PreviousDisabled`, and `ProgressLabel`/`NextLabel` text attributes (the counter and next control paint them). The dots iteration, selector anchoring/placement, outside-click/Escape dismissal, storage/auto-start and the step-change/complete callbacks are withheld or pending; no overlay is created.

`Links` is the anchor scaffold: the host carries the declared destination metadata (`Href`, `Target`, `Rel`) and size carriers, and `LinkControl` raises an `Activated` request with the href when the host is clicked while enabled. The runtime never navigates, exposes no visited state and `Disabled` disables pointer activation; the consumer decides what activation means.

`Image` is the native media element: the generated class derives `UnityEngine.UIElements.Image`, `ImageControl` interprets the declared `Src` string as a Resources-relative texture asset and assigns the host image (clearing the source clears it), and the radius/size axes project carrier classes. URL fetching, alternative text, intrinsic width/height, aspect ratio, fit/position, loading strategies and fallback sources are refused rather than approximated.

`Avatar` is the guarded media composition: the generated root composes an admitted `Image` child and an initials `Label`, both shown only when their declared string prop is non-empty (`Src` / `Initials`); `AvatarControl` owns both presence toggles, forwards the source to the child image control and paints the initials text, and the size vocabulary projects carrier classes. The name/priority props, the decorative alt and the aria-label binding are refused; no assistive label or loading priority is claimed.

`NavTree` is the nested navigation scaffold: `HeadingLink`/`HeadingLabel` are the two polarities of the page-link prop (the label shows while `Href` is empty, the link once it is set), `Label` paints both texts, `Link` exposes the activation request, and the `List` is the class content container so consumers compose child trees into it (`NavTreeItem` is generated for item composition). The glyph icon subtree is omitted pending P4 glyph composition, so `icon`/`iconSize` and the `aria-current` current-page state are refused rather than approximated.

`Postcard` is the static projection host: the article renders its header/content/footer sections inline, the body insertion is the class content container, and the visually painted object-path leaves are projected as flattened string attributes (`AuthorName`, `AuthorHandle`, `Timestamp`, `StatsLikes`) that paint their labels, because UXML attributes cannot bind nested object properties. The object-valued `author`/`stats`, the post id, the embed and the machine-readable datetime/aria-labelledby wiring are refused rather than serialised.

`Pagination` is the numeric page strip: the generated class exposes `Index`/`DefaultIndex`, a `Pages` string array, `Disabled`, `Controlled`, `OnIndexChange`/`PageRequested` callbacks and the presentation/progress carrier classes; `PageStripControl` builds one native button per label with the authored item/marker/fill/label classes, commits uncontrolled activation, raises a request in controlled mode and blocks activation while disabled. Current-position styling (authored `data-current` selectors) and the accessible navigation label are withheld rather than faked; the visible labels are the consumer-authored page strings.

`OTP` is the one-time-password field group: the generated class exposes `Length`, `Value`/`DefaultValue`, `Mode` (numeric or alphanumeric filtering), `Disabled`, `ReadOnly`, `Controlled`, `ValueRequested` and `OnChange`/`Completed` callbacks; `OtpControl` builds one one-character native text field per position, distributes pasted characters, joins the cell characters into the value channel, ignores characters the mode rejects, and fires completion when every position is filled. Disabled/read-only apply to every field. The accessible group/field labels and describedby wiring are withheld, as are platform keyboard/autofill hints.

`RadioGroup` is the native choice group: the generated class declares a nested option type built from the iteration bindings (`RadioGroupOption` with the declared value/label/description/disabled leaves), and exposes `Options`, `Value`/`DefaultValue`, `Controlled`, `ValueRequested`, `OnChange` and the `Orientation` carrier. `ChoiceGroupControl` translates the typed options to parallel leaf arrays and builds one native `RadioButton` per option with the authored item class, declared label, description tooltip and per-option disabled state; selection commits uncontrolled changes or requests them in controlled mode. The authored internal item markup, data-state selector styling and the form `name` are not reproduced.

`Select` is the two-channel listbox: the generated class declares a nested `SelectOption` type from the iteration leaves and exposes `Options`, `Value`/`DefaultValue`, `Placeholder`, `Disabled`, the open channel (`Open`, `DefaultOpen`, `OpenControlled`), both change/request callbacks and the size carrier. `SelectControl` builds the option buttons into the options host, paints the trigger label from the current option or placeholder, toggles the listbox surface and the authored open class from the open channel, commits or requests a single selection and closes after choosing. Multi-select, search/filtering, the empty state, keyboard roving, the aria mirrors and the authored aria-selected/data styling are withheld.

Values assigned before attachment provide initial state. For owner-controlled state, set `Controlled = true`, handle `ValueRequested`, and commit an accepted value through `Checked`, `Open`, `Value` or `Values`. A request alone does not change presentation. This is a C# adaptation of the contract's controlled/default channel trio; C# event signatures use arrays for both Accordion selection modes.

Popover portals content to its current panel root. It uses the anchor/content union for outside-pointer and blur dismissal, returns focus to the trigger on Escape, and flips/shifts at panel edges. Dismissal flags remain configurable. Removing a Popover unregisters its panel callbacks and removes the floating content.

## Runtime styling

`Runtime/Resources/FullStackDS/Controls.uss` is generated by `pnpm run generate:unity` from the token graph and the admitted contracts' style facts; do not edit it. Its token section declares the tokens the controls reference through `resolvesTo` or emitted literal `var()` reads as USS variables named as the web token build names them (`--fsds-semantic-color-foreground-primary`): light values on `.fsds-theme`, dark values on `.fsds-theme.fsds-theme--dark`, and each brand on `.fsds-theme.fsds-brand-<name>` and its dark variant. The component rules select the part classes (`switch__track`, `tabs__tab`, …), the root modifiers (`switch--lg`), the behavior state classes (`is-checked`, `is-open`, `is-selected`) and native pseudo-classes. Each declaration USS cannot realise is listed with its reason in `Controls.unsupported.json` beside the sheet (for example CSS grid, box shadows, `line-height`, `font-weight: 500`, `cursor`).

An ItemGroup's hidden-content presence fact lowers `:not([hidden])` onto its content state class, so open Accordion content receives its opacity and padding rules. A literal graph `var()` without an authored fallback receives the graph's light value as a fallback for controls outside a theme scope.

Four visible gaps follow from facts this projection does not carry:

- The Accordion chevron is the contract's static `componentRef: fsds.Icon` (`chevron-down`). The walker constructs the admitted Icon, forwards its authored name and size, and paints catalog geometry through `GlyphElement`. Dynamic reference bindings and references to unadmitted targets fail generation.
- The chevron's rotation while expanded (`[aria-expanded="true"]`) and the selected-tab styling (`tab--active`) use selectors outside the native style grammar; they are `uss-selector` ledger entries until the IR carries them as state predicates.
- Brand overrides of component design slots are `uss-design-slot` ledger entries; brands reach the controls through the token variables only.
- Button's contract styles a loading spinner and loading-text chrome, but the generated action control omits the guarded Spinner decoration and flattens the loading-text wrapper (both pending-P4 chrome). The sheet still carries the contract's `button__spinner` and `button__loadingText` rules, which have no live elements in the generated control.

Controls add the stylesheet to their own root but do not open a theme scope there, so the scope belongs to a consumer container:

- `Theme.Attach(container)` adds the stylesheet and the `fsds-theme` class (light, default brand).
- `Theme.SetDark(container, bool)` selects the dark or light values; `Theme.SetBrand(container, "canary")` replaces the brand class, and `null` selects the default brand. Both attach the container first. Brands are not validated: a name the sheet does not declare matches no rule, so the default brand's values apply.
- The nearest element carrying `fsds-theme` decides the values for its subtree.
- A control with no scope above it resolves the `var()` fallbacks in the sheet: the light values of the default brand. Dark and brand switching have no effect on it until a scope is attached above it.
- Popover content is moved to the panel root while open, outside the container. It carries its own scope and mirrors the dark and brand classes of the scope its Popover sits in, on every open and on every `SetDark`/`SetBrand` call.

Two runtime pieces realise facts USS cannot express. Switch mirrors its hidden form control's pointer and focus state onto the root as `is-hover`, `is-active` and `is-focus`, because the contract styles the track from the control's state and USS cannot select a sibling; the focus ring is therefore drawn on the track. `is-focus` follows UI Toolkit focus, which has no focus-visible distinction, so pointer focus shows the ring too. USS has no `gap`; the sheet sets `--fsds-gap` and the generated constructors call `Gap.Attach`, which turns it into a margin between consecutive in-flow children (absolutely positioned and `display: none` children are skipped; the margin replaces the child's own margin on that side).

`Samples~/InteractiveControls/Sample.uss` is sample-only consumer styling, not package theme authority, used by the sample and the Editor showcase: page layout, title and description typography, a skin for Unity's built-in buttons, labels and scrollers. It reads the generated token variables, selects built-in classes at single-class specificity and is attached before `Controls.uss`, so any property a generated rule sets wins. The sample UXML attaches it to the root and to `PopoverContent` (open content leaves the root's tree); the showcase finds it by its GUID once the sample is imported and otherwise runs on the generated sheet alone. Consumer overrides should target the part classes, root modifiers and state classes; floating content lives outside the originating container, so apply overrides to `popover.Content` as well.

`PanelSettings` still owns screen scaling. The visual witnesses use **Constant Pixel Size**, scale 1, at 640×800 and 320×600. A consumer using **Scale With Screen Size** and a 960×640 reference can shrink the entire interface in a small Game view. Choose the scale mode and reference resolution for your game; the package does not overwrite them. Reimport the sample from Package Manager to update a previously copied sample.

## Regenerate and verify

From the repository root:

```sh
pnpm run generate:unity
pnpm exec vitest run packages/ds-codegen/src/frameworks/unity/factory.test.ts
pnpm run audit:unity-boundary
pnpm run test:unity
```

`audit:unity-boundary` checks that every contract and sidecar leaf in the corpus resolves to a support-boundary rule, that no allowlisted component relies on a catch-all rule and that every rule matches at least one live leaf; it prints counts per disposition and pending counts per parity phase.

## Pilot boundary

The allowlist is in the repository's `fsds.targets.json`. The Unity backend is selected by `--target=all` but is outside the TypeScript admission rail. Its EditMode lane is local and explicit, not an existing CI gate.

[`support-boundary.json`](../ds-codegen/src/frameworks/unity/support-boundary.json) is the machine-readable statement of what the Unity target lowers, leaves pending for a named parity phase, or refuses, with the mechanism or reason for each rule. Generation fails when a contract carries a fact no rule classifies, when an allowlisted component relies on a catch-all rule, or when a lowered claim is not realised by the control a component gets; see [Support boundary](../../docs/architecture/unity-target.md#support-boundary).

This slice implements the interactions above. It does not claim full framework parity, screen-reader integration, controller/gamepad navigation, cross-platform player-build admission, or full visual parity. Styling is the generated projection described above; what it does not realise is listed in `Controls.unsupported.json`. Transitions keep their properties and durations, but a non-keyword easing is reduced to `ease`. The Accordion chevron paints its Icon componentRef; expanded-state rotation remains an unsupported selector. The action control carries no loading affordance, ARIA state or HTML form serialization. The boolean controls expose no indeterminate/mixed state and no form fields. The passive containers expose only carrier-backed style axes and their consumer content region; Blockquote's citation URL and ProfileFlag's structured profile data are refused/pending rather than approximated. Badge's guarded node-content icon decoration is omitted, with `icon` pending P4 and `showStatusIcon` refused. List exposes only its Variant and Size axes: `as` is refused, `marker` is refused because USS has no `list-style-type`, and `spacing` is pending P4. Alert and AlertNotice are static containers whose guarded icon and dismiss chrome is omitted; the dismissal callback, flag and label, and the composed action control, are pending P4. Label exposes no form association and Breadcrumbs exposes no a11y label or separator. Tooltip's content is non-interactive and its ephemeral presence makes no retained-state promise; it exposes no outside-click dismissal. Status omits its decoration icon instance and exposes no icon API. Card's interactive hover affordance is pending P4 and its link region is consumer-composed. NavList withholds its orientation axis (no USS carrier) and exposes no a11y label. Skeleton omits its iterated row anatomy and claims no shimmer animation; multi-line skeletons are pending P4. Table's responsive overflow and aria labeling are pending/refused and its keyboard/sort navigation is not realised. CodeBlock omits its syntax-highlight transform, token stream, gutter and line numbers; per-line highlighting and `white-space: pre` are not approximated. Details closed-state chevron rotation, ARIA state/label and the native `<details>` element are not claimed; its content is hidden rather than unmounted. Progress projects a plain value prop to a native width and exposes no channel, formatted value text, circular variant or ARIA value tree. Chip renders native action chrome rather than composed Button instances, so the Button component styling, form type, ARIA state/label and icon content are not claimed. CodeSnippet projects its text and modifier classes only; the code/kbd/samp element switch and the kbd elevation shadow are not claimed. Browser form props and DOM IDs are not ported. Tabs keeps an inactive panel's object state even when detached.
