# Godot comparative pilot

`GODOT-COMPARATIVE-PILOT-01` adds an explicit Godot target and compares it with Unity using the frozen [semantic traces](../../packages/ds-godot/fixtures/traces.json). See [package instructions and limits](../../packages/ds-godot/README.md).

The lowering path is contract → ComponentIR → GDScript/PackedScene/Theme resources → shared Godot Control runtime. Dispatch uses value model, interaction operation, surface attachment, passive anatomy shape, projected action content, and composition class, not component identity. The generated controls carry operation and declared defaults; only the bounded behavior named in the capability receipt is realized. Unsupported shapes reject emission; excluded composite props and style declarations are named in their receipts rather than receiving support credit. Passive text and rule shapes use the shared static-content runtime. Their style configuration is projected from normalized native style rules and token facts, including variant-scoped overrides. Projected actions use a separate shared runtime that resolves source-ordered token and style rules at render time, including size, intent, hover, pressed, focus, disabled, and token/design-slot overrides.

Compound parts and icon-decorated content use a shared composite runtime. The generated PackedScenes contain named part hosts, so changing density, intent, size or token overrides updates StyleBox and Label resources without replacing consumer children. Empty optional hosts leave the layout until visible content enters them; adding or removing an icon changes spacing while preserving the host and its other children. Card and Badge exercise this class: a Card can retain generated Text, Badge and Button instances in its named parts, while Badge accepts a string label and consumer-provided Control in its icon part. Root and part styles resolve token definitions within the addressed part; a child part's token redefinition cannot alter the root. The local Editor and fresh exported macOS Player witness checks nested action delivery, identity retention, optional-part spacing, style override precedence, changed Card and Badge background pixels, and rendering and action delivery from a separately saved and reloaded composite scene.

An `iconGlyph` fact selects the shared glyph plan without inspecting the component name. The generated Icon scene uses `runtime/glyph.gd` and a package-level catalog projected from every authored iconography variant and path attribute. Name and size bindings, size token styles, decoration and accessible-name sources come from the IR; an unlowered prop, selector, style declaration or anatomy fact rejects emission. The plan admits square token dimensions and rejects rectangular dimensions until the renderer can preserve SVG aspect ratio. The renderer selects the largest authored grid at or below the requested size, paints the authored SVG in the contract frame, inherits the Label foreground for `currentColor`, and clears the texture for an unknown name. A package-local Godot project imports the scene, checks rendered texture pixels and live inherited color updates, saves/reloads Icon properties through editor APIs, and runs the same glyph probe in a fresh macOS Player export. The observed `accessibility_name` and decorative flag are structural projections; screen-reader behavior is not established.

A passive, single full-turn rotation loop with an authored ring border selects a shared loop-visual plan before the generic anatomy planner. The generated Spinner scene carries the target part, 800 ms timing, cubic easing, four size values, three thickness values and authored track/accent colors into `runtime/loop_visual.gd`; unrelated loop families continue to their own planners and capability receipts. The runtime paints two source-colored arcs, uses the theme font size and authored base border width when axes are unset, and accepts an explicit reduced-motion input that holds the authored static angle. The local Godot 4.7.2 pilot checks default and large/bold geometry, a quarter-period turn, reduced-motion hold and separate accent/track viewport pixels in the runtime and a fresh macOS export. Arc rasterization approximates the Web border-top shape; inline layout, delayed presentation, OS preference integration and screen-reader behavior remain unproved. The capability receipt names the excluded `inline` and `showAfterMs` props.

A static `componentRef` under an item trigger carries the normalized target name, part identity and validated string or enum prop attributes into the control configuration. The shared control runtime mounts the admitted glyph scene as a trigger child and forwards those props; referenced targets without the glyph mount capability, invalid enum literals, string attributes targeting boolean or numeric props, dynamic bindings, children and other placements fail generation. The Accordion's authored Icon reference exercises this path. The glyph probe mounts a renamed host, checks a static accessible-name attribute, and checks catalog geometry, inherited foreground and viewport pixels in the local runtime and a fresh macOS export.

The initial common observations cover uncontrolled/disabled boolean state, controlled request versus commitment, collapsible single selection, disabled tab selection and surface toggling. Godot's native CheckButton and scene tree replace Unity UI Toolkit's button/visual tree. The surface uses a CanvasLayer within the viewport. This is a substrate choice, not a change to the shared state trace.

The test fixture saves/reopens serialized Switch and composed Card scenes through editor APIs, checks token fallback values in loaded Theme resources, executes graphics-backed observations and exports a fresh macOS application. The comparison runs Unity Editor-panel traces against Godot runtime/export traces. It requires matching run IDs and exact expected sequences. It does not claim input-device integration, accessibility, arbitrary composition, full visual parity or shared traces executed in a Unity Player.

For Switch, Accordion, Popover, and Tabs, the foreground Theme projection is intentionally narrow. Its changed-token probe reads `Theme.get_color()` and frees the probe before rendering; that observation does not prove rendered consumption. Text and Divider have a separate runtime witness: Text content, variant font size and weight, line spacing, and Divider orientation, thickness, margin and changed token color are checked on live Label and ColorRect nodes in the Editor and exported macOS Player. The action witness checks Button content, a focused `ui_accept` input path, activation suppression while disabled or loading, size and intent styles, native state styleboxes, and a changed token color sampled from the viewport image in both Editor and exported macOS Player. These are source-identified local observations, not a general visual or input-device parity claim.

The passive fixture also saves and reloads Text and Divider in the fresh project, then checks constrained Text width against its natural width, nondefault alignment/case/truncation settings, horizontal and vertical rule geometry, and rule pixels sampled from the rendered viewport. `pnpm run test:godot` copies the verification scripts their saved scenes load before Editor import, runtime checks and macOS export. The integrated run at clean source `d1926e18c` on Godot 4.7.2 passed the passive, Icon, action and interaction rows in both runtime and exported Player; `/private/tmp/fsds-godot-passive-integrated-20261030/provenance.json` records the source revision, clean-tree flag and trace digest. A viewport pixel match for a rule does not prove typographic pixel parity.

`DSButton` exposes string `content`, `activated`, `variant`, `size_axis`, `axis_values`, `token_overrides`, `disabled`, `loading`, `aria_label`, and `title` through the shared action runtime. Authored defaults initialize action state before consumer overrides. Its capability receipt names the unsupported CSS and selectors, including state-specific typography and geometry and unused content gap. Native Control composition for arbitrary Web children is unlowered; Godot's indeterminate ProgressBar approximates the referenced Spinner. HTML `type` and `ariaExpanded`/`ariaPressed` are excluded. Authored transition rules and platform-restricted visual declarations are not silently treated as engine styling. Godot font metrics, rounded letter spacing, integer line spacing and String-based case transform remain target approximations. Text accepts string content but not the contract's node-ref children. `Text.as` and `Divider.decorative` remain excluded semantic props, so these admitted components do not establish full cross-target fidelity or accessibility parity. The generated passive capability receipts name each gap. Expanding component admission follows capability decisions and independent consumer workflows, not the number of scenes that compile.

Card's `title` slot has no normalized compound-part carrier, and its interactive link/focus behavior and authored shadow/motion declarations are unlowered. Badge does not synthesize the prose-described status glyph; `showStatusIcon` is excluded until the contract supplies an executable default-glyph fact. Root role and labeling projection, arbitrary nested Button content, screen-reader delivery for Icon, and cross-platform visual fidelity remain open. The composite capability receipts enumerate each unsupported selector, declaration and prop; that accounting is not itself semantic or visual proof.

At source `62f37334`, comparison run `5af9bd21-83b8-4e79-ad7c-6fa825ccc9a2` passed the frozen cases against Unity 6000.5.3f1 and Godot 4.7.2. The Godot macOS export used the matching export template, Compatibility rendering, and ETC2/ASTC texture import. Run evidence includes `comparison.json`, per-engine receipts, editor serialization logs and an exported screenshot. Source trees and the trace file are hashed in the comparison receipt. The default `standalone` feature-name assumption was rejected during harness development; the exported witness uses Godot's `template` feature tag.

## Corpus-wide admission and the support boundary (GODOT-UNITY-COMPONENT-PARITY-01)

The registry allowlist now matches the Unity target's component set: all 55 corpus contracts emit GDScript, PackedScene and Theme resources. Widening admission from ten components to the corpus was a capability slice, not a registry edit — the emitter gained two planning shapes and a boundary discipline.

**Planning shapes.** The bounded shapes stay first in dispatch and are unchanged for the components that already used them (sequence, bounded glyph, composite, projected action, narrow static text/rule, narrow anchored surface, boolean/select/toggle-item control). Three additions sit behind them:

- **Generic anatomy** (`walker.ts`, `runtime/anatomy.gd`): lowers an arbitrary `ir.dom` / `ir.parts` / `ir.compoundParts` tree into named part hosts and a flattened scene, projecting the style declarations it can map and naming every fact it cannot. It declines any shape a bounded planner already claims, and declines `ir.surface` so overlays keep their presence semantics.
- **Wider presence surfaces** (`surface-plan.ts`, `runtime/surface.gd`): blocking modals, viewport-edge sheets, transient toasts, selector-anchored coachmarks and hover/focus tooltips that the narrow anchored shape could not represent. The runtime realises presence only — an open flag, `open_changed`, inert declared-prop projection and plan-fact getters. It deliberately implements no backdrop, focus containment, dismissal gesture, anchoring, stacking or timer, and each missing behaviour is named in the receipt.
- **Prop boundary** (`boundary.ts`, `support-boundary.json`): a committed, ordered ledger that classifies every contract and sidecar leaf as `lowered`, `pending` or `refused`, ending in a catch-all so an unadjudicated family fails generation instead of becoming a silent exclusion.

**Discipline.** Every generated component carries a `capabilities.json` receipt naming its exclusions and omissions; `pnpm run audit:godot-boundary` (script `write:godot-boundary` regenerates the inventory) enforces three separate obligations: ledger totality (no admitted component may rely on an unadjudicated leaf), receipt totality (every excluded prop is named in that component's own omissions or fidelity gaps), and inventory drift (the committed `packages/ds-godot/verification/capability-inventory.json` must match a fresh regeneration). Where a shape legitimately declines a fact the target lowers elsewhere — a presence-only surface cannot lower a dismiss timer — the audit records a shape variance rather than failing, so the disagreement between per-target ledger and per-shape capability stays visible and reviewable.

**What this does not claim.** Emission parity is not behavioural parity. The anatomy shape emits a loadable scene tree, projected style subset and inert declared props; data-driven iteration emits one host and names the repeats, componentRef instances emit an empty host, and channels, focus, validation, formatting, motion, keyframes, messages, a11y roles/labeling and CSS layout semantics are omissions in the receipts, not realisations. The pilot's `catalog-load` row proves every admitted scene exists, parses and instantiates — it is a structural admission witness, not a behaviour witness. Typography and glyph rendering keep the approximations recorded above. The Godot target remains outside the TypeScript admission rail and CI drift diff; this slice adds a local boundary audit, not rail admission.
