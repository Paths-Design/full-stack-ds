# Unity UI Toolkit pilot

`UNITY-INTERACTIVE-COMPONENTS-01` adds a registered Unity generation target with a bounded component allowlist and a local UPM package. Read [the package README](../../packages/ds-unity/README.md) for installation, supported behavior, commands and limitations.

The lowering path is `ComponentIR → anatomy walker → C# UXML elements → attached runtime behaviors`. The walker ([`walker.ts`](../../packages/ds-codegen/src/frameworks/unity/walker.ts)) lowers `ir.dom`, or a tree synthesized from `ir.parts` when a contract declares no `dom`, into one generated root class and one per `ir.compoundParts` entry. A passive text root with a single content insertion derives `TextElement`, and a passive text-content host whose root content is a declared string prop derives `TextElement` with a generated text attribute; other admitted roots derive `VisualElement`. The behavior dispatcher ([`behaviors.ts`](../../packages/ds-codegen/src/frameworks/unity/behaviors.ts)) selects which runtime behavior the generated constructor attaches: a boolean form-control fact selects `BooleanControl`, a single `select`/`toggle-item` interaction trigger with hidden presence selects `ItemGroup`, a part-anchored, non-blocking surface selects `AnchoredSurface` (click mode toggles from the trigger; hover/focus-open mode is selected when the surface declares hover/focus open triggers with non-interactive ephemeral content), a single `toggle` interaction trigger with unmount presence and no surface selects `Disclosure`, a surface-less contract whose decoration carries a CSS-variable style binding from a declared numeric prop selects `Progress` (the numeric value becomes a native percentage fill width and an optional presence-guarded label), a centered, persistent, viewport-attached blocking dialog surface or a viewport-edge blocking sheet selects `Modal` (portal, backdrop, focus trap, dismissal knobs, and for a sheet a runtime edge-placement axis), a slot-only composition container (no interaction/surface/form-control, a channel and named slot hosts) selects `Slots` (the scaffold renders the slot hosts and carrier axes but withholds the context channel), a prop-bound anchor root selects the `Anchor` scaffold, an `<img>` root with a prop-bound source selects `Media`, a guarded Image child plus a guarded text fallback selects `Avatar`, an href-guarded link/label heading pair with a child-list insertion selects `Tree`, a numeric index channel over an iterated button item selects `PageStrip`, a boolean channel over an always-mounted content slot with a state-dependent trigger label (and optionally a declared clamp presence and boolean expandable guard) selects `Expansion` (ExpansionControl owns the channel and label painting), a `sequence` block (`motion.sequence`) over a numeric index channel with declared slide labels/controls/timing selects `Sequence` (SequenceControl owns wrapped navigation, viewport switching and the autoplay dwell), a `pagedSet` block over a numeric position channel with declared page items selects `PagedSet` (PagedSetControl owns bounded navigation and the one-based draft commit), a `transfer` block over a string[] channel with the declared available/selected collections selects `Transfer` (TransferControl owns the dual lists and derivation), a selection channel plus a boolean open channel over a guarded listbox surface selects `Select` (SelectControl builds the options and owns both channels), a string selection channel over an option array with a channel-checked leaf selects `ChoiceGroup` (a nested option type is generated and ChoiceGroupControl builds native radios), a string value channel over counted single-character inputs selects `Otp` (OtpControl materialises the fields and assembles the value), (PageStripControl builds the item buttons from the declared label list and owns the index semantics), nested-property text leaves with a body insertion select `ProjectedText` (flattened attributes paint the labels; object props are withheld), (NavTreeControl owns the heading polarities and paints their text; the glyph subtree is omitted), (AvatarControl owns both presences and paints the fallback), (the class derives the native Image element and ImageControl loads a Resources texture), (destination metadata carried as generated attributes, activation raised through LinkControl, no navigation), a persistent non-blocking coachmark renders the `Coachmark` inline scaffold (step attribute, slot hosts, native control callbacks; anchoring/messages/iteration withheld), a non-blocking ephemeral viewport-edge toast selects `Toast` (ToastSurface portals the host, owns presence, the auto-dismiss timer, the title paint and close/Escape requests), a text form control selects `TextInput` (the generated class derives the native TextField when the form-control part is the root, or wraps the native field child when the wrapper carries named slots; TextControl adapts the string channel in both shapes), a projected-children action root selects the `Action` path, and a contract whose only action is a trigger component reference with a click callback binding selects composed action chrome (native buttons with generated callback properties). A parts-only contract with no dom tree, channel, interaction or surface selects the same passive lowering: the walker synthesizes the tree from `ir.parts` and each explicit subcomponent part becomes a composed class. An unsupported-unadmitted shape throws. No rule branches on component, part, channel or class identity; the one name table is the item-group option vocabulary (`type`, `collapsible`, `orientation`, `activationMode`, `loop`, `appearance`, `unmountInactive`), applied only when `ItemGroup` was selected by fact. [`lore.test.ts`](../../packages/ds-codegen/src/frameworks/unity/lore.test.ts) scans the emitter for predicates against lowercase part, channel and prop literals and admits only that table. See [Anatomy walker](#anatomy-walker) for the rules.

A projected-children action root lowers to a native action control instead of a behavior-carrying `VisualElement`: the generated class derives `UnityEngine.UIElements.Button`, its `contentContainer` is the control itself (the contract's loading-text wrapper is flattened), the DOM click binding becomes a generated `Action` property invoked from the native `clicked` event (pointer activation and Space/Enter submit alike), a bound `disabled` prop drives `SetEnabled`, and carrier-backed variant axes reuse the class-recipe modifiers. The guarded loading decoration is a conditional componentRef (pending P4), so the lowering omits it; the loading, ARIA-state and HTML form-type facts are refused by the support boundary. Native trigger parts name `UnityEngine.UIElements.Button` explicitly so the generated `FullStackDS.Button` element cannot capture them.

The three interactive runtime behaviors are plain C# classes, not `VisualElement` subclasses. They own Unity event delivery, selection and focus state, dismissal and panel coordinates, and discover the composed sub-elements they pair by part class under their host. The passive `GlyphElement` is a hand-written `VisualElement` renderer: the generated Icon wrapper supplies its glyph name and size, and a generated C# catalog supplies authored geometry. The action path adds no runtime class: the generated control itself is a native UI Toolkit button. Runtime code does not read JSON contracts.

Verification has separate boundaries: TypeScript tests check routing and contract influence; compiler-only checks use real Unity reference assemblies and the UXML generator; EditMode tests require an activated Unity Editor and exercise import plus live panel events. The existing `governed:rail` does not execute the Unity lane. Neither compilation nor narrow EditMode facts establish full styling, accessibility or player runtime parity.

## Icon glyph and static references

An `iconGlyph` fact selects the passive Icon lowering. The shared authored iconography catalog supplies each named path and size variant; the Unity catalog emitter parses supported SVG path commands into C# drawing commands and fails on unsupported grammar. The generated Icon wrapper exposes `Name` and `Size`, and the hand-written `GlyphElement` paints those commands with UI Toolkit `Painter2D`. Size selects the largest authored grid at or below the requested frame. The renderer reads its resolved foreground, repaints on color changes, and clears an unknown name without a fallback glyph. This is a local rendering contract, not assistive-technology exposure or pixel equivalence with Web SVG.

For a static `componentRef` to an admitted target, the walker constructs that generated target element and forwards resolved literal prop attributes. Accordion's trigger mounts its authored `Icon` chevron through this path. Dynamic reference bindings, child-bearing references and references to targets outside Unity's allowlist fail generation. The source tests rename the containing component while preserving the nested Icon fact; Editor tests exercise direct glyph pixels, and the standalone Player samples direct and composed glyph pixels inside their own bounds.

Unity's [custom-control documentation](https://docs.unity3d.com/6000.0/Documentation/Manual/UIE-create-custom-controls.html) defines the partial-class / `UxmlElement` registration mechanism. Unity's [package layout documentation](https://docs.unity3d.com/6000.0/Documentation/Manual/cus-layout.html) defines Runtime, Editor, Tests and Samples packaging.

## Styling projection

The package stylesheet `packages/ds-unity/Runtime/Resources/FullStackDS/Controls.uss` is generated, not authored. [`uss.ts`](../../packages/ds-codegen/src/frameworks/unity/uss.ts) runs through the `emitTargetAssets` seam of the codegen CLI after a full-corpus Unity run and writes two assets: the stylesheet and the unsupported ledger `Controls.unsupported.json` beside it. The CLI records only rail targets in the emission manifest, so these assets stay outside it until P5 admission.

The sheet has two sections. The token section declares every consumed `--fsds-*` custom property from `resolved.tokens.json` on `.fsds-theme`, overrides it on `.fsds-theme.fsds-theme--dark`, and layers each brand from the token build's brand layer on `.fsds-theme.fsds-brand-<brand>` in both themes. Its closure includes both IR `resolvesTo` references and graph variables read by emitted literal declarations; refused or substituted declarations do not add token definitions. The brand section also declares every brand-layer variable that resolves to a USS scalar, including brand-only roles no admitted component reads yet, so a consumer lane can address those variables as its override channel; Orion's projected scope grew from 93 light / 68 dark variables to 217 light / 123 dark. The component section lowers `ir.nativeStyleRules`, the same framework-neutral style facts the GPUI target reads, into one USS rule per part, variant, state and pseudo predicate. State predicates land on the runtime's state classes (`is-checked`, `is-disabled`, `is-hover`, `is-active`, `is-focus`) at the host the behavior sets them on; variant predicates land on the `<prefix>--<value>` recipe classes; floating content restates its component scope because it leaves the component's subtree; a composed-content host repeats its owner's container facts so composed children lay out as the contract describes.

USS is a subset of CSS, and the projection lowers rather than copies. Logical sides become physical LTR sides, `inline-flex` becomes `flex` with a row direction, `outline` becomes a focus-only border, `gap` becomes the `--fsds-gap` custom property that the runtime's `Gap` helper realizes as child margins (a ScrollView's in-flow children live in its content container, which does not inherit the host's custom properties, so `Gap` resolves that container itself). A declaration with more than one component never carries `var()`: USS keeps only the variable and silently drops the other components. Each variable in such a declaration is resolved across every scope the sheet emits (light, dark, every brand, every definition of that component slot, and the declared fallback). A value that is the same in every scope is inlined. A slot redefined under a state is restated under that state's selector, unless the restatement could win the cascade where CSS would not (more than one varying variable, a variable defined on both the element and an ancestor, a consuming rule with its own state, or another rule setting the same property); those cases, and values that vary by theme or brand, are ledgered. Keyword-valued USS properties take the same path: a token-fed `font-weight` maps the resolved token, not the sidecar fallback, to `-unity-font-style`, and is ledgered when it varies by scope. A graph token the sheet leaves undefined is ledgered rather than replaced by its fallback. Everything the projection cannot express is written to the ledger with a reason (`uss-property`, `uss-scalar`, `uss-pseudo`, `uss-pseudo-element`, `uss-selector`, `uss-owner-mismatch`, `uss-floating-scope`, `uss-design-slot`, `uss-var-composite`) instead of being approximated. The support boundary classifies the token and style sidecar leaves these rules consume as `lowered` and the ledgered families as `refused` or `pending`; the emitter never reads the boundary.

For native typography, one authored `rem` is resolved to 16px in token values and in the font-size/letter-spacing property lowerings. This fixed baseline makes Text's size and typography variant carriers executable in USS; it does not model a consumer-adjusted root font size. Relative `em`, unsupported font weights, line-height, `text-transform`, and style selectors using DOM attributes remain ledgered.

The runtime selects scopes rather than values: behaviors attach the sheet without adding `fsds-theme`, consumers call `Theme.SetDark` and `Theme.SetBrand` on an ancestor, and floating content mirrors its owner's theme classes. `Samples~/InteractiveControls/Sample.uss` carries sample-only skin for Unity's built-in controls at the lowest specificity; it is not package styling.

The normalized `:not([hidden])` selector becomes a presence predicate. For an ItemGroup with hidden content, Unity selects it through the state class the runtime applies to the paired content part; this restores open content opacity and padding. Other owners remain refused. Literal graph variables emitted without an authored fallback receive the graph's light scalar as a `var()` fallback so an unscoped control retains its default transition timing.

## Anatomy walker

`UNITY-ANATOMY-WALKER-01` replaces the per-shape wrapper emission with a generic walk. The rules, each read from IR facts:

- **Classes.** A passive text root with a single content insertion derives `TextElement` so its string `text` paints; a projected-children action root derives `UnityEngine.UIElements.Button`; a boolean form control whose form-control part is its button root derives the same native button and exposes `Trigger => this`; other component roots derive `VisualElement`, plus `INotifyValueChanged<bool>` when the selected channel is boolean. Each `ir.compoundParts` entry becomes `<Name><Part>` with a base chosen by fact: `UnityEngine.UIElements.Button` for a trigger part (the form-control part, an interaction trigger or the surface anchor) or a `button` tag, `ScrollView` for interactive surface content, otherwise `VisualElement`. Compound nodes emit nothing inline in their parent; the consumer composes them, as on the web.
- **Part identity.** Every rendered part sets `name = "<part>"`; the root carries the `cssPrefix` class and every other part `<cssPrefix>__<part>`. Non-compound parts inside a class are public read-only element properties in document order; a trigger part is a `Button`, a text leaf with literal content a `Label`, and a static admitted glyph `componentRef` is its generated component type. Other nodes are `VisualElement`s. Static reference name and size props are assigned from the resolved component-instance IR; targets without the glyph mount capability, unsupported glyph props, dynamic bindings, children and unadmitted references reject emission. Passive roots attach the generated stylesheet to themselves without opening a theme scope.
- **Insertion points.** A `children` hole that is its parent's only child makes that parent the `contentContainer`. Otherwise a private `children` host (class `<cssPrefix>__children`) sits at the hole's position and becomes the container. The same host is inserted at the first compound node's position when rendered siblings follow it, so composed sub-elements keep document order. A named slot becomes a public `<Slot>Slot` host. More than one hole, iteration and conditional guards other than the content-presence guard throw `UNITY_UNSUPPORTED_ANATOMY`. A guarded decoration whose content is a dynamic node prop (`nodeKind: node-ref`) has no static projection: the passive lowering omits it by fact, and the boundary refuses its anatomy subtree while keeping the node-content prop pending P4. A guarded action chrome — a native button or componentRef element carrying an event binding, guarded by a declared boolean prop — is likewise omitted by fact, with its props, bindings and event refused and the composed action control pending P4. A passive root also ignores DOM-metadata bindings — a11y `role`/`aria-*` attributes, and the label's `htmlFor`/`form` association — none of which UI Toolkit renders; the boundary classifies those leaves refused or pending. A decoration-role component instance is omitted by role fact (component composition is pending P4); the boundary refuses its subtree and part identity, and a generated member that would share its class name takes a `Value` suffix (`Status.StatusValue`). A subtree containing `iterate` anatomy is omitted by fact (iteration is pending P4): the boundary classifies its props, parts and selectors, and the projection ledgers the iterated rows. A node whose content is a content transform is likewise omitted by fact; its transformed subtree and owned parts are refused and its source/token/line-number props stay pending P4. A text leaf bound to a declared string prop lowers at generation time to a `Label` plus a root string `UxmlAttribute` that paints its text (R5b); the walker asserts the binding is a string and refuses a non-string or non-text-leaf binding, and a prop named like a rendered part keeps its identifier while the element accessor is suffixed.
- **Props.** Channel members become the channel API (`ChannelName`, `ChangeHandler`; boolean: the value attribute, `value`, `SetValueWithoutNotify`, `RequestValue`, `Controlled`, `ValueRequested`; string: `Value`, `Values`, `Controlled`, `ValueRequested`, `ValueChanged`). The interaction's `disabledProp`, or a `disabled=prop:*` binding on the form-control part, becomes `Disabled`. A variant axis the attached behavior consumes (an item-group vocabulary entry, or the surface placement prop) becomes a validated string attribute that swaps the root modifier class `<cssPrefix>--<value>` (the web class recipe) through the runtime `Variants` helper and drives the behavior knob; every other axis (Switch `size`) is a styling axis, emitted as the same validated attribute and modifier class when the generated stylesheet carries a rule keyed on that modifier, and withheld when no behavior knob and no stylesheet rule consumes it. A colliding axis disambiguated by the class recipe's `valuePrefix` emits `Variants.GetAxis`/`SetAxis`, which key the prefixed spelling (`list--marker-disc`), and its USS rule carries that prefixed class. Dismissal `enabledBy` props and the placement prop come from `normalizedDismissalTriggers` and `surface.positioning`. Trigger sub-elements get `Disabled`; the ItemGroup trigger and content sub-elements get `Value` and implement `IKeyedPart`, the pairing key.
- **Behavior attachment.** After the tree is built the constructor calls `BooleanControl.Attach`, `ItemGroup.Attach`, `AnchoredSurface.Attach`, `DisclosureControl.Attach` or `ProgressControl.Attach` with options read from the IR (a blocking modal passes its content, overlay and close trigger plus the state class; a text input derives or wraps TextField and attaches TextControl, which adapts the native change event to the string channel (a wrapper keeps its slot hosts and attaches to the child field); a toast passes its item, close control, title label and state class to ToastSurface, which portals the host and runs the timer; composed action chrome needs no runtime class: the generated constructor wires each native button click to its callback property and initializes guard flags): the control part and a `labelHost` when the root tag is `label` (a click on the label toggles the control once), trigger and content part classes, the operation, `multiple` from the channel type, focus strategy, orientation and wrap, and the state class. A root-control boolean passes `control: this` and `Trigger => this`; every other boolean passes the rendered child as the control. The state class is `is-<value>` for the non-initial value of the first `effect: channel` state dimension, else the selection dimension: `is-checked`, `is-selected`, `is-open`. A disclosure passes the rendered trigger button and content element, and the runtime toggles the content's display presence alongside the `is-open` class; the trigger is also the class's `Trigger` accessor. A value-fill passes the rendered fill and optional label elements plus the range read from the root's `aria-valuemin`/`aria-valuemax` literal bindings, and the runtime clamps the value and writes the fill's native percentage width; the label's presence follows the generated show-value flag, and the authored calc-var width is refused rather than projected.
- **Geometry.** Generated C# sets no inline geometry; every size, padding and gap fact reaches the element through the generated stylesheet (see [Styling projection](#styling-projection)), so a consumer's USS can override it.

Consumer composition follows the contract's compound parts rather than runtime-invented item types: `<ds:Accordion><ds:AccordionItem><ds:AccordionHeader><ds:AccordionTrigger value="a" text="A"/></ds:AccordionHeader><ds:AccordionContent value="a">…</ds:AccordionContent></ds:AccordionItem></ds:Accordion>`, `<ds:Tabs><ds:TabsList><ds:TabsTab value="a" text="A"/></ds:TabsList><ds:TabsPanel value="a">…</ds:TabsPanel></ds:Tabs>`, `<ds:Popover><ds:PopoverTrigger text="Help"/><ds:PopoverContent>…</ds:PopoverContent></ds:Popover>`, and a Switch's label is its children. Behaviors discover composed parts on panel attach, on layout change, before pointer or submit input reaches a trigger, and on public API calls; a part inserted into an already attached root shows its state at the next of those events, or immediately after `Group.Synchronize()`.

[`factory.test.ts`](../../packages/ds-codegen/src/frameworks/unity/factory.test.ts) drives the walker with synthetic contracts outside the corpus (different part names, a named slot, a hole with siblings, composed content followed by a rendered sibling, a parts-only shape, knob-driven and withheld variant axes) so the output is shown to be rule-derived rather than corpus-shaped. The walker does not consult the support boundary; the boundary describes the walker and `assertRealized` checks the two agree.

## Capability inventory and standalone boundary

`UNITY-CAPABILITY-PLAYER-01` introduces reproducible source accounting:

```sh
pnpm --filter @full-stack-ds/codegen build
node packages/ds-codegen/dist/frameworks/unity/capabilities.js > tmp/unity-capabilities.json
node scripts/unity-player.mjs
```

The inventory walks the authoritative contract loader and registry. Each component receives a lowering `status`; each normalized prop is classified as `emitted-api` or `not-emitted` and carries the support-boundary rule for its family. Every contract and token/style sidecar leaf is listed individually with the disposition (`lowered`, `pending` or `refused`) and rule id that the [support boundary](#support-boundary) assigns it. Contract/sidecar hashes bind the observations to their inputs. The inventory is accounting, not proof of semantic parity; the generation gate belongs to the support boundary. `not-emitted` means no matching generated C# property: a callback can be lowered through a shared-runtime C# adaptation and a default channel through imperative initial assignment, and the boundary records each such adaptation as an explicit `via` mechanism rather than crediting it from property names.

The inventory finds only the allowlist admitted. Checkbox and ToggleSwitch pass the shape dispatcher but are unadmitted candidates; that does not establish their intended anatomy or behavior. Most other corpus shapes are rejected as `unsupported-shape`. The pilot emits no generated C# property for default channels, callback props, form fields, or Tabs idBase; Switch `size` is emitted because the generated stylesheet carries its modifier rules. The boundary records the channel defaults and callbacks as `lowered` through runtime adaptations, Switch `name`/`value` and Tabs `idBase` as `refused` DOM-only fields, and the styling axes as `lowered` through the stylesheet projection. An unknown prop on an allowlisted contract is listed as `not-emitted` in the inventory and fails generation until the boundary adjudicates its family.

## Support boundary

`UNITY-SUPPORT-BOUNDARY-01` commits the machine-readable statement of what the Unity target lowers, defers and refuses: [`support-boundary.json`](../../packages/ds-codegen/src/frameworks/unity/support-boundary.json), validated against [`support-boundary.schema.json`](../../packages/ds-codegen/src/frameworks/unity/support-boundary.schema.json) and evaluated by [`boundary.ts`](../../packages/ds-codegen/src/frameworks/unity/boundary.ts). The file is an ordered rule list; the first matching rule wins. Every contract leaf and every token and style sidecar leaf resolves to exactly one rule, and each rule carries one disposition:

- `lowered`: the Unity emitter or the shared C# runtime realises the family. `via` names the mechanism, such as `RegisterValueChangedCallback` for a boolean channel's change member or pre-attachment assignment for a channel default.
- `pending`: a later parity phase lowers the family. `phase` names it and `reason` states what is missing. The phases are P2 (generic anatomy walker), P3 (styling projection), P4 (interaction families) and P5 (corpus and admission); the file's `phases` block summarises each. P2 is discharged; P3 is currently used only by the boolean controls' withheld size axis, whose contracts carry no size-predicated style rules.
- `refused`: UI Toolkit cannot realise the family idiomatically, and `reason` states why. Examples: HTML form submission fields have no form element to serialise into, USS has no `@keyframes`, and ARIA roles and relationships have no assistive-technology consumer.

The validator rejects a `lowered` rule without `via`, a `pending` rule without a phase and reason, and a `refused` rule without a reason. Only `pending` rules may be catch-alls.

Leaves are identity-keyed JSON pointers. An array element that carries a `name` or `part` is keyed by that identity rather than by its index. A prop member is keyed `<role>:<name>`, where the role comes from the contract's own `channels` and `form` blocks: `channel-value`, `channel-default`, `channel-change`, `form-field`, or `plain` for every other prop. Tabs' `value` is therefore keyed `channel-value:value`, while Switch's `name` and `value` are form fields because Switch participates in forms. Rules classify pointer families and never name a component. A `lowered` disposition says the family has a lowering; the component's inventory `status` says whether the dispatcher applies it to that component.

A `tokens:` or `styles:` rule may add a `declaration` condition that tests the whole sidecar declaration (one token entry, or one property of one styles block) rather than a single leaf, so every leaf of a declaration classifies alike. `valuePattern` matches the declared value (the literal, else the fallback); `nativeGrammar` asks whether the IR's native style grammar admits the block's selector key, which depends on the component's own parts and variants and so is answered by building the IR, not by a key pattern. The rules that refuse what the USS projection cannot express (properties USS lacks, cursor, non-zero outline offset, unmapped font weights, transitions the projection only partly realises, `calc()`, tokens that are not a single USS value) and the pending P4 rule for selector keys outside the native grammar sit ahead of the blanket `tokens` and `styles` lowered rules.

Any rule may also declare a contract-level precondition (`requiresAny`): it applies only when the same contract declares a leaf satisfying the listed pointer and value condition. The precondition is evaluated against the whole contract, so it disambiguates prop families the identity-keyed pointer cannot separate — the DOM button `type` versus an item group's selection `type` — without naming a component. A styles declaration condition may also test the block's selector key (`keyPattern`), which refuses pseudo-element and web-only pseudo-class blocks generically.

### Generation gate

The Unity emitter implements the codegen `admitContract` hook. The CLI's generate path calls it once per component with the validated contract, sidecar tokens and styles merged, before any lowering; watch mode passes the bare contract without the sidecar merge. A refusal fails generation like an emitter error, including under `--dry-run`. The gate has two refusals:

- `UNITY_BOUNDARY_UNCLASSIFIED`: a leaf matches no rule. Generation fails for every component, allowlisted or not.
- `UNITY_BOUNDARY_UNADJUDICATED`: an allowlisted component carries a leaf that only a `catchAll` rule matches. Catch-all rules classify unknown families as `pending` so that nothing is silently supported, and an allowlisted component may not rest on one. Widening the allowlist, or adding a prop to an admitted contract, therefore fails generation until a family rule in the boundary file decides it.
- `UNITY_BOUNDARY_UNREALIZED`: a `lowered` rule that declares `realizes` does not hold for the control this component gets. `emitted-property` requires the prop to be a generated public property, `selected-channel` and `selected-channel-member` tie channels and their props to the one channel the dispatcher selected, and `channel-change-event` requires an event to be emitted through that channel's change prop. A prop whose name belongs to a lowered family of another base (`orientation` on a Switch), a second channel, or an unrelated event is refused rather than dropped.

The dispatcher refuses by fact what a runtime behavior would otherwise contradict: a focus strategy that does not match the behavior (`UNITY_UNSUPPORTED_FOCUS`), a portal on a non-surface shape (`UNITY_UNSUPPORTED_PORTAL`), a surface whose portal is disabled, whose presence is not persistent, whose content is not interactive, whose interaction presence is not unmount, or whose dismissal trigger has no `CloseOn*` knob (`UNITY_UNSUPPORTED_SURFACE`), and a state model with no single projectable value (`UNITY_UNSUPPORTED_STATE`). Those refusals are what allow the matching families to be classified `lowered`.

An explicit `generate <Name>` request that bypasses the allowlist tolerates catch-all leaves but not unclassified or unrealised ones. The hook is admission only: it builds the IR to check realisation and derives no emitted source, so the generated C# does not depend on the boundary.

### Audit

`pnpm run audit:unity-boundary` builds the codegen package and runs the capability inventory in `--check` mode over the whole corpus. It fails on any unclassified leaf, on any allowlisted component that relies on a catch-all rule, on any dead rule that matches no live leaf, and on any allowlisted component whose control does not realise a lowered claim. It also joins the generated `Controls.unsupported.json` to the boundary: each ledger entry maps by exact pointer to its sidecar leaves, and a backing leaf classified `lowered`, or an entry with no backing leaf, is a violation. Brand design-slot entries come from the token build's brand layer and token-section entries from the token graph, not from any contract or sidecar leaf, so the join skips them. It prints leaf counts per disposition and pending counts per phase. [`boundary.test.ts`](../../packages/ds-codegen/src/frameworks/unity/boundary.test.ts) pins the same audit, so the root `pnpm test` run in CI enforces it. The tests also pin role derivation from `channels` and `form`, identity keying, first-match ordering, `valueIn` filtering, both refusal codes and rejection of malformed rule files.

### What the boundary does not prove

The boundary is accounting plus a gate. A `lowered` disposition records that a family has a lowering; it is not semantic or runtime proof that the lowering is correct, and behavior evidence comes from the EditMode and Player witnesses above. Refusals are revisable decisions about UI Toolkit, not permanent exclusions. The `a11y` refusal, for example, holds only while UI Toolkit populates no assistive-technology tree, and the rule names that integration as the trigger to revisit it. Unity remains outside the TypeScript admission rail, and its EditMode and Player lanes are local runs, not CI gates.

The ledger join only covers allowlisted components, because only they have a generated ledger. Across the rest of the corpus the blanket `styles` and `tokens` rules can classify families the projection would refuse as `lowered` (`inset`, the `transition-*` longhands, unsupported relative lengths, `position: fixed`, `inherit` and `currentColor`); admitting such a component makes the join fail until a narrower rule decides them. The boundary classifies a font weight by its declared value, while the projection decides by the resolved token, so the two can disagree for a component outside the allowlist.
